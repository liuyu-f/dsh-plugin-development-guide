基准运行时：`@deepseek-ai/dsh` **0.2.0-rc.2**（Windows 桌面端 + Web）。

## 这份文档的写法

- **正文只写不随版本变的东西**（机制、契约、判据、动作顺序、有代价的取舍）；
  随版本漂移的值一律进 `版本快照/<版本>/`，正文只留"去哪查"。
  原因见指南 §2.2 —— 写死一张会过期的表，比不写更糟。
- 每条结论带证据标记：✅ 本机实测 ｜ 📖 随包文档/源码 ｜ ⚠️ 风险提示。
- **不保留"不确定"的条目**：查不清的要么删掉、要么给出一条能查清的判据。
- 方法论（怎么区分"观测"与"结论"、模型文档最容易犯的错）在指南 §14 与工作流 §8 ——
  这两节即使你不写 DSH 插件也值得读。

## 仓内自检

```sh
# 1) 文档完整性：相对链接是否都有效、中英镜像是否成对
node 版本快照/0.2.0-rc.2/_tools/docs-integrity.mjs .

# 2) 清单自检：拿它检查你自己的插件目录（路径/形状/一致性等静默失败）
node 版本快照/0.2.0-rc.2/_tools/清单自检.mjs <你的插件目录>

# 3) 解包随包文档与前端产物（asar 里的东西普通命令读不到）
node 版本快照/0.2.0-rc.2/_tools/asar-extract.js "<安装目录>/resources/app.asar" \
     "/dsh/node_modules/@deepseek-ai/dsh-client-ui-workspace" "_ref/ui-workspace"
```

## 版本快照怎么维护

升级 DSH 之后：**复制**上一版目录成 `<新版本>/`（不要就地改旧版，旧版是别人排查历史问题的依据），
按每份文件里"升级后怎么重查"那一列重新取证，再更新索引表并跑一遍文档自检。
细节见 [版本快照/README.md](版本快照/README.md)。
