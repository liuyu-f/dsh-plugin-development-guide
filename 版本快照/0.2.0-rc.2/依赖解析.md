# 安装方式 × 裸 import 解析（`0.2.0-rc.2`）

> 中文 ｜ [English](dependency-resolution.en.md)

**结论先行**：插件能不能裸 `import '@deepseek-ai/*'`，**只取决于插件的真实路径在不在 profile 目录下面**——
与包名是不是 `@deepseek-ai/*`、与"官方规范是否要求零 import"都无关。

## 判据（在插件目录里跑一条命令）

```sh
node -e "console.log(require.resolve('@deepseek-ai/dsh-tools'))"
```

打印出路径 = 能 import；`MODULE_NOT_FOUND` = 不能。

## 三种安装方式（本机实测）

| # | 安装方式 | 真实路径 | 裸 import | 备注 |
|---|---|---|---|---|
| 1 | 工作区目录 `link:` 进 profile（开发常态） | 你的工作区（如 `F:\...`） | ❌ `ERR_MODULE_NOT_FOUND` | **即使把依赖装进 profile 也一样失败** |
| 2 | 工作区目录里自己 `pnpm install` 过 | 仍是工作区路径 | ✅ | 依赖在插件自己的 `node_modules` 里 |
| 3 | `pnpm pack` 成 tarball / 发布 registry / 从 git 安装 | **profile 的 `node_modules` 内** | ✅ **实测通过** | 真实路径在 profile 下 → 命中 profile 的 `node_modules` |

## 支撑方式 3 的那次实测

探针插件（`private`，仅为验证）：

```json
{ "name": "@local/dep-probe-tarball", "type": "module", "main": "index.js",
  "exports": { ".": "./index.js", "./package.json": "./package.json" },
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } },
  "dependencies": { "@deepseek-ai/dsh-tools": "0.2.0-rc.2" } }
```

```js
import { defineTool } from '@deepseek-ai/dsh-tools'   // 静态具名 import：模块加载期就执行
```

步骤：`pnpm pack` → `pnpm add file:<tgz>`（装进 profile）→ 激活该 bundle。结果：

| 观测 | 值 |
|---|---|
| 行是否激活 | ✅ 激活成功（不再 `failed to import`） |
| 工具是否注册 | ✅ `dep_probe_tarball_report` 出现在工具表且可调用 |
| 工具自报 | `static import … -> OK`、`defineTool is a function: true` |
| `import.meta.url` | `file:///C:/Users/<user>/.dsh/profiles/desktop/node_modules/@local/dep-probe-tarball/index.js` |

## 两个容易误判的点

1. **`link:` 不安装被链接包的依赖**（最小对照实测：消费者与被链接包两侧都没有 `node_modules/<dep>`，`.pnpm` 里也没有）。
   所以"我在 package.json 里声明了依赖，`install_bundle` 就会替我装上"**只在方式 2、3 成立**。
2. **依赖装在 profile 里、不等于 link 进来的插件能读到**。这恰恰是方式 1 反直觉的地方：
   即便 profile 的 `node_modules/@deepseek-ai/dsh-tools` 存在，从工作区真实路径出发的那次向上查找也到不了它。
   （顺带一句：Node 从 profile 内的 junction 路径解析是**能**找到的——但 Host 真正用的是插件的真实路径。）

## 附：清单里另一个静默失败（同批实测踩到）

`exports` 的**每个键都必须写 `.` 或以 `./` 开头**。写成 `"package.json"`（少 `./`）会让**整个 `exports` 字段非法**：

- Node 抛 `ERR_INVALID_PACKAGE_CONFIG`；
- 插件管理页对该插件显示红色 **"包元信息错误"**（`Invalid package config … "exports" cannot contain some keys starting with '.' and some not.`）；
- 该行**不会激活**。

判据：`node <版本快照>/_tools/清单自检.mjs <插件目录>` —— 它现在会直接点名这个键。
