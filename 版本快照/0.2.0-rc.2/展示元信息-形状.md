# 展示元信息的形状（`0.2.0-rc.2`）

> 中文 ｜ [English](display-metadata-shape.en.md)

**结论：`locale/<lang>.json` 必须是 `{"meta": {"title": …, "description": …}}`（嵌套）。**

顶上直接放 `title` / `description` 的**扁平写法是无效的**——读取器只看 `parsed.meta`，
扁平文件不会报错，只是**整份被忽略**，显示回落到 `package.json` 的 `name` / `description`。

✅ 源码 `dsh-app-boot/lib/index.js` 的 `dictionariesOf()`：

```js
const meta = parsed.meta === void 0 ? void 0 : objectOf(parsed.meta, `${file}: meta`)
dictionaries.set(id, {
  title: textOf(meta?.title, `${file}: meta.title`),
  description: textOf(meta?.description, `${file}: meta.description`),
})
```

`readPluginMeta()` 的回落链：本地化字段缺失 → 同一个 `package.json` 的 `name`（title）
与 `description`；title 的最终兜底是**完整模块标识**，description 的最终兜底是空串。

## 本版本确实在用嵌套的文件（抽样）

```
@deepseek-ai/dsh-client-ui-schedule/locale/en.json   {"meta":{"title":…,"description":…}}
@deepseek-ai/dsh-…（asar 内 locale/(en|zh|ja).json 全部 20 份，均为嵌套）
```

## 两种形状对照

```jsonc
// ✅ 有效：读取器认这个
{ "meta": { "title": "删除会话", "description": "从会话头部或侧栏会话菜单彻底删除会话。" } }

// ❌ 无效且不报错：整份被忽略 → 显示 package.json 的 name / description
{ "title": "删除会话", "description": "从会话头部或侧栏会话菜单彻底删除会话。" }
```

## 顺带区分三个"meta"

| 出现在哪 | 形状 | 作用 |
|---|---|---|
| `package.json` 顶层 `meta` | `{ "title": …, "description": … }`（**扁平**） | 清单内联的展示文本（可选） |
| `locale/<lang>.json` | `{ "meta": { "title": …, "description": … } }`（**嵌套**） | 按语言的展示文本；与上面同名但形状不同 |
| `package.json` 顶层 `icon` | 相对路径字符串 | 图标（≤256 KiB，相对 manifest 目录） |

**验证判据**：把 `package.json` 的 `description` 临时改成一句好认的英文，
若管理页显示的是你 `locale/zh.json` 里的中文，说明嵌套形状被读到了；
若显示的是那句英文，说明 locale 文件被忽略了。
