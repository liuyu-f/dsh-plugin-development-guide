# 版本快照

> 中文 ｜ [English](README.en.md)

这里放**某个版本上当场查到的值**。正文（[DSH-插件开发指南.md](../DSH-插件开发指南.md)）刻意不写这些值，只写"去哪查"——
本目录就是那些查询结果的落脚点。

**怎么用**：写代码卡在"这个名字/字段到底叫什么"时，进对应版本看一眼，然后**在你自己的版本上重查**；
两者不一致时以你查到的为准。

| 目录 | 基准运行时 | 里面有什么 |
|---|---|---|
| [0.2.0-rc.2/](0.2.0-rc.2/) | `@deepseek-ai/dsh@0.2.0-rc.2`（Windows 桌面端 + Web） | 种子表、展示元信息形状、ownerProps、MCP 字段、诊断文案、解包与机检脚本、**一个实装验证过的最小插件** |

**归档一个新版本**（升级 DSH 之后）：

1. 复制上一版目录（`0.2.0-rc.2/` → `<新版本>/`），**不要就地改旧版** —— 旧版快照是别人排查历史问题的依据；
2. 按每份文件里"升级后怎么重查"那一列重新取证，把值替换掉；
3. 更新上面的表和每个版本的 `README.md`；
4. 跑一遍 `node <新版本>/_tools/docs-integrity.mjs ..`（链接与中英镜像成对性）。

> 这是"查询结果的存档"，**不是接口也不是承诺**；`_ref/` 才是"你这次要抄的参考实现"。
> 两者都是用完即弃，只是归档方式不同。
